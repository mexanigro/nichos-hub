## Diferencia comprobada y consecuencia

1. N solo: browser y ambos runtimes seleccionan synthetic-n; ambas notificaciones devuelven false sin fetch simulado, aunque permiso y configuración sintética del agente están completos.
2. C contiene sólo espacios y V válido (o N/V espejados): browser/servidores encuentran id válido; ambos agentes devuelven null/false, sin intento.
3. C ausente,N=synthetic-n,V=synthetic-v: servidores seleccionan n y ambas funciones efectivas de notificación emiten un payload con v. Se observa el JSON en fetch sustituido, no se envía tráfico.

La distinta prioridad del navegador no prueba por sí sola un bug. Con variables contradictorias incumple la igualdad ya documentada: bootstrap y servicios browser apuntan a su V, mientras rutas servidor usan N/C. Trazado mínimo adicional: BookingWizard:175–197 excluye clientId del body y no envía header tenant; createBookingHandler:59,67,74 deriva reserva/clientes del id servidor. Por tanto no debe suponerse un rechazo403 automático de ese recorrido ante contradicción. No se volvió a ejecutar reserva ni se afirma una escritura real: se conservan book-v1 y se identifica el desacuerdo de partición por código actual. Las configuraciones contradictorias deben detectarse y corregirse con autorización en la preparación del despliegue; esta reparación local no migra ni reconcilia entornos reales.

## Única recomendación de contrato compatible

Conservar las variables y prioridades del navegador y de ambos runtimes. Todas las variables no vacías configuradas para una misma instalación deben representar el mismo id exacto tras trim; no inventar default, cambiar case, aceptar selector del visitante ni resolver conflictos cambiando silenciosamente de tenant. V/N públicos deben corresponder al id efectivo servidor. La carga de variables entre build/runtime sigue como condición de despliegue N08, no certificada por este sondeo.

Para el agente, resolver **C.trim()→N.trim()→V.trim()→vacío**, igual que el servidor. Si no hay id, seguir sin notificar. El permiso AGENT_ENABLED=true sigue obligatorio; credenciales presentes no habilitan. Se conservan firma/payload salvo el id corregido, URLs/auth, límites, mensajes, canales y los resultados base. No introducir un bypass ni apagar globalmente el agente para aparentar conservación.

Cambio mínimo futuro: una expresión en getAgentkitConfig de src/lib/notify-agentkit.ts y otra en api/index.ts. server.ts y navegador quedan sin cambios de producto. Actualizar sólo documentación pertinente de clientId en README.md/.env.example para reflejar aliases, prioridades y coherencia exigida; no modificar .env real. No hace falta módulo compartido nuevo ni ampliar imports. Proyecto, databaseId, claims, pagos, provisioning y resto de RE-EXT-02/03 no se resuelven aquí.
