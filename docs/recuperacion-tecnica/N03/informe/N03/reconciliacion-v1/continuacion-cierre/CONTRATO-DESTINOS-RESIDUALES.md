# Tres selectores residuales REST
Regla vigente de coincidencia cuando ambos destinos definidos. Runtime state, guard tenant y payment credentials mantienen selección VITE→NEXT, bases FIREBASE→VITE→literal default, retornos incompletos/sin token. Si proyecto Admin/configurado (FIREBASE_ADMIN_PROJECT_ID→FIREBASE_PROJECT_ID) definido y difiere del seleccionado, rechazar antes del fetch. No elegir otro proyecto ni imponer configuración dual. Comparar llamadas y retornos reales de callbacks extraídos, no variables solas. Son tres consumidores concretos; otros inlineREST/browser permanecen en misma fila del balance.
Refutación: sustituye la prioridad FADMIN→FIREBASE propuesta por comparaciones separadas contra FADMIN y FIREBASE definidos. Si alguno contradice el proyecto elegido, rechazo; no ocultar contradicción entre ellos. Antes se conservan retornos sin proyecto/token. Matriz fija10casos×3callbacks,90comparaciones deURL/base/retorno/error; no sólo conteos.
